Graduate from your laptop to a shared hub without starting over

When teammates, CI pipelines, or unattended agents join, export your local app copies and reasons directly to confighub.com or a self-hosted server. Every cub command and starter stays the same.

What a shared hub adds

A local hub protects one developer's machine. A shared hub connects people, CI jobs, and running services to one signed source of truth.

One key per agent, instant revocation

Issue a scoped key for each unattended agent or CI job. Agents propose in parallel without clobbering each other, and cub mini revoke-agent cuts off any key on its next request.

Agents that run for weeks

Named team approvers and Slack

Require named owners to approve production orders from Terminal or from the Slack thread where the work started. Approving revision 3 never pre-approves revision 4.

Hosted or self-hosted

  • Hosted: Sign in to confighub.com and restore your exported copies.
  • Self-hosted: Run your own ConfigHub server with cub-server and connect with the same cub CLI.
  • Web UI & SDKs: Inspect revisions in the MIT-licensed Web UI or automate with the Go SDK and JS SDK.

Live delivery stays with your existing tools

  • PaaS & cloud: Deliver approved settings to Vercel, Fly.io, AWS Parameter Store, or VMs via pull.
  • GitOps over OCI: Publish immutable release digests that Argo CD, Flux, or Sveltos reconcile automatically.
  • Git beside the hub: Keep .cub-mini records in commits and PR comments alongside hub approvals.
