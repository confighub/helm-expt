How one app lives in Mini Hub

Connecting an app does not rewrite your repo files. ConfigHub creates three copies of its settings and an optional isolated preview, plus a scoped key for the agent.

Shared source

app-base

Shared settings and starter defaults, each with a written reason. Changes start here once.

Agent can update

preview

A running local copy on its own port that survives across chats while leaving your usual app alone.

Agent can update

app-staging

Takes base changes right away so your agent can verify behavior before proposing to live.

Owner approves

app-live

Agent proposes a change order on its scoped key; the hub refuses self-approval until you approve.

Explicit CLI

Attach any repo or run in CI and sandboxes

Works with .env, Compose, Terraform, and Kustomize repos, or inside a disposable CI job with one hub per run.

cub mini install
cub mini adopt . --name myapp
cub mini require-approval myapp --variant live --agent myapp-agent
cub mini waiting

Install Mini & checksums · CI & sandboxes

Review, approve, refuse, or roll back

The agent proposes changes using its own scoped key. You inspect and decide in your own terminal using the order IDs shown below.

cub mini waiting

Review the proposed values. To approve one, run cub mini approve BASE/ORDER with the exact ID shown. To decline it, run cub mini refuse BASE/ORDER --reason "Why". You can leave it pending and come back later.

To undo an approved change, run cub mini rollback APP-live --change-order BASE/ORDER --reason "Why" with your app and order. Review the new proposal before production changes.

No lock-in and a clean exit ramp. Your original files are never modified during adopt. At any point you can export every setting back to plain files and stop or remove the local hub. Going back and uninstalling · Approvals detail.
