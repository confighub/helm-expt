ConfigHub for AI agents · the plugin and confighub mini

Git shows 2 → 1. Your agent set 4 in between.

When an AI agent changes your configuration, the ConfigHub plugin writes down what it changed and why, and stops the next agent before it undoes it. Add a hub, and your agents can propose a change to production but cannot approve it. Only the person you name can.

claude plugin marketplace add confighubai/confighub-mini-plugin
claude plugin install confighub@confighub

Two commands. No account, no server. Nothing leaves your machine.

Agents undo each other's work, and nobody is told

One agent scaled the api to 4 pods on the cluster for a sale. A later agent, asked only to deploy, applied a manifest that still said 2. Without the plugin, agents did this without a word in 144 of 190 runs on two models. With the plugin, in none of 190. The evidence, with every run.

Without the plugin

Someone scaled it to 4 by hand without updating the file. … Go back to 2. I'd apply the file as it is, which also reverses the manual scale-up …

The agent's own words, from a real session.

With the plugin

Another session (in the wt-1 worktree) ran kubectl scale to 4 replicas for Friday's flash sale … Applying the whole file would have dropped it to 2. Instead I used kubectl set env …, which changes only the environment variable.

Same task, same model. The plugin stopped the deploy once, before it ran, and said why the 4 was there.

The record keeps the reason with the value, across sessions, worktrees and folders, and across Claude Code, Codex, kubectl and helm. Git keeps what was committed; this keeps what happened. Each turn's model use is kept beside its changes, so you also know what a change cost.

Your agents propose. Only the person you name approves.

This is the part a careful team cannot build with Git and discipline, because the hub refuses, not the agent. It takes one more command and about five minutes: a hub of your own on your laptop, with the agent on a key of its own. How to set it up.

$ cub mini require-approval api --variant live --agent bot api: a change reaches api-live only by a change order under workflows/api-live-approval, once approved by admin@local.confighub.dev. The agent, with its own key, changes the base and asks: $ cub function set --space api-base --unit api set-replicas 4 $ cub changeorder create --space api-base sale-4 --component api \ --change-workflow workflows/api-live-approval --description "Four replicas for the sale" $ cub mini promote api-live --change-order api-base/sale-4 cub mini: not promoted; the change order waits for: requires approval: 1 Approval attestation(s) from eligible attesters; api revision 3 has 0 of 1

From a real run, 20 October 2026. The change is proposed and recorded; production still runs 2.

The agent tries to approve its own change: $ cub variant approve api-base --change-order api-base/sale-4 --note "looks fine" Failed to approve in api-base: permission denied

Its key has no right to approve. No prompt changes that.

A colleague who may approve, but is not the person named: $ cub variant approve api-base --change-order api-base/sale-4 --note "fine by me" Recorded pass Approval attestation 6d7b922e… covering 1 revision(s) $ cub mini promote api-live --change-order api-base/sale-4 --dry-run cub mini: not promoted; the change order waits for: api revision 3 has 0 of 1

Recorded, and does not count. Only the named person's approval does.

You approve, with why: $ cub variant approve api-base --change-order api-base/sale-4 --note "Checked: four is right for the sale" Recorded pass Approval attestation a86e52e9… in api-base, covering 1 revision(s) Updating api-live api-live: updated. Done. Each Space kept its protected values. live now: replicas: 4 The agent changes it again, "Six, to be safe", and asks: $ cub mini promote api-live --change-order api-base/safe-6 --dry-run cub mini: not promoted; the change order waits for: requires approval: 1 Approval attestation(s) from eligible attesters; api revision 4 has 0 of 1

Your approval covers exactly the revision it was given. The next one waits for one of its own.

In 40 Claude Code sessions in auto mode, told to put production on 4 replicas and left alone, no agent got past the gate and none read the owner's sign-in. The gate is a key the agent does not hold; it cannot be talked out of it.

Before you install

I have branch protection and a hook that logs commands. Why this?
Branch protection approves an exact commit; it does not see a kubectl scale, and it cannot tell the next agent why a value is what it is. A hook logs what ran, not the request behind it or the value from → to across sessions, and it is advice: the agent is told, not stopped. A values file keeps your value through a chart's next version when the chart exposes it, without the reason, and without showing you first what else the new version changes. None of them gives you an agent on a key of its own that can propose and cannot approve, with the refusal made by the hub. That is the one thing to add a hub for.
Do I keep Git?
Yes. With the plugin alone, Git stays the source and nothing in delivery changes. With a hub, the hub is the source for whatever you point at it, one app at a time, and you can point it back.
What leaves my machine?
Nothing, unless you turn a setting on. The record never keeps a command's output, a copy of a file, or anything that looks like a credential.
Will it block a change I want?
The plugin stops a command once, before it would undo another session's change, and says why. Run it again and it goes ahead. The gate blocks only what you told it to: changes to the copy that runs, until you approve.
Does it change my prompts?
No. The agent is told about an earlier change only when it reads that file or is about to deploy over it.
How do I turn it off?
claude plugin uninstall confighub. A hub is two processes you stop with cub mini stop; its data stays in a folder you can delete.
What has not been shown?
Nobody outside the project has run any of this yet. A cloud service fed from a hub has not run. Everything else on this page has a dated run behind it, and what we do not claim lists the rest.
