Three caveats that apply to every chart (cub-direct path)

  • Customize with `--input` or a base edit, not Helm's `--set` — cub rejects `--set`/`--values` (the typo guard); declared values use `--input`, the rest by choosing/editing a kustomize base.
    Managed: Guided errors + migration cheat-sheet (#1020, docs/user/helm-to-cub-migration.md).
  • Upgrades don't auto-delete removed objects on cub-direct — A plain `kubectl apply` leaves orphans when an upgrade removes a resource.
    Managed: Managed applier uses `--prune` (#1019), or use a controller (Argo/Flux) which prunes natively.
  • A manual `kubectl edit` conflicts on server-side re-apply — Safer than Helm's silent overwrite, but a Helm user expects the overwrite.
    Managed: Managed applier surfaces a plain-words message + `--force-conflicts` (#1019).

Use a controller (Argo/Flux) and all three are handled for you; on bare cub-direct the managed applier (#1019) handles them.
