Serverless parity

No account: Helm vs cub installer in two kind clusters

This is the cleanest parity check. The harness installs regular Helm into one vanilla kind cluster, applies the cub installer output into another, and compares the live object meaning.

npm run kind-parity:run -- --chart bitnami/redis --version 27.0.0 --base default

Open two-cluster parity receipts

Connected parity

ConfigHub path: Helm vs ConfigHub OCI/GitOps

This checks the connected path: ConfigHub publishes the rendered object set as OCI, Argo reconciles it, and the live result is compared with regular Helm.

npm run live-parity:run -- --recipe recipes/bitnami/redis/25.5.3 --base default

Standard Redis

Follow the smallest happy path

Redis is the teaching chart: render the public package, verify your local render against the catalog, and then choose whether to apply locally or upload into ConfigHub.

cub installer setup --pull packages/bitnami/redis/25.5.3 --base default --work-dir .tmp/redis --non-interactive --namespace redis
npm run redis:verify-install:render -- --base default --work-dir .tmp/redis --namespace redis

2. Show Me What I Can Do

Once parity is visible, the value is that the rendered objects become explicit config. You can review them, create variants, apply policy, promote changes, and observe the live result.

CapabilityWhat it meansWhere to look
Create useful variantsBase variants capture Helm render choices. Derived ConfigHub variants handle approved post-render changes such as target, labels, gates, links, and observation policy../variants.html
Review and operate objectsOnce rendered objects become ConfigHub Units, teams can diff, scan, approve, promote, observe, and audit them instead of treating Helm as one opaque action../operations.html
Build apps on the dataSeveral charts plus a custom service can become one managed desired-state graph with scans, diffs, promotion, and GitOps handoff../custom-apps.html

3. What Are The Limits?

The homepage should not hide the hard parts. Render parity is a baseline. Hooks, CRDs, webhooks, target facts, existing Secrets, cloud identity, storage, and controller-owned runtime state need explicit routes.

LimitMeaningWhere to look
A green render is not production proofTarget facts, lifecycle behavior, hooks, controller state, storage, and cloud identity can still matter.../docs/user/target-prerequisites.md
Watch is not fail, and not passA watch row means parity may hold while a target, runtime, lifecycle, or support decision remains visible../matrix.html
Some chart choices need new basesIf a values file, overlay, CRD choice, Secret mode, HA mode, or extension slot changes Helm output, create or import a new base and prove it.../docs/user/custom-overlays.md

Open hard questions for the skeptical path through hooks, upgrades, custom values, target prerequisites, GitOps sync, and free versus managed boundaries.
