Who We Are And Why This Exists

ConfigHub builds software for managing Kubernetes configuration as data. cub is our open source CLI. ConfigHub Server is the connected product for teams that need shared desired state, variants, approvals, OCI/GitOps delivery, and operations.

Helm works well until every real app needs one more tweak: a Secret model, a CRD choice, a customer overlay, or a pinned old version. The chart still works, but the customisation becomes hard to see.

This site is our public experiment for that problem. The community can try the serverless path without a ConfigHub account: compare Helm with cub, inspect the generated Kubernetes YAML, and choose a chart from the catalog.

When you want ConfigHub to hold the desired state, the connected path begins with commands such as cub helm install. For maintained catalog entries, we also publish reviewed cub installer packages and compare them with ordinary Helm. When both paths get the same deployment, we call that parity.

The Problem

Every app and user eventually needs their own tweak: values files, old chart versions, generated Secrets, CRDs, webhooks, hooks, cloud identity, ingress rules, storage, and target-specific overrides.

Those choices are normal, but they pile up. Which version is pinned? What will break in the next upgrade? Why did this deployment fail? Which change is safe to promote?

What ConfigHub Adds

ConfigHub stores Kubernetes desired state as structured, versioned config. The YAML Helm would create becomes data you can inspect, diff, gate, deliver, and observe.

3. Verifying What We Can And Cannot Do With This Model

Comparing with Helm is the start of the story. Real deployments can still need an existing Secret, storage class, cloud account, CRD, webhook, or setup job.

A matching render is the first check.

It proves the starting objects, not that every target cluster already has the right Secret, storage, or cloud account.

Cluster prerequisites

Some charts need extra setup.

CRDs, webhooks, certificates, hooks, and setup jobs should be visible before the install path is trusted.

Chart actions

Some choices need a new base.

If a values file changes what Helm would render, make and prove a new base rather than quietly editing the output.
