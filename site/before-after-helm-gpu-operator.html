Before and after

See what the GPU Operator Helm chart becomes

Plain helm template renders 27 objects for the NVIDIA GPU Operator v26.3.3, and 8 of them are Helm hooks that must never be applied with the rest. The Catalog's bundle holds the 24 objects to apply, with the 5 CRDs first, and a plan that says when each hook runs.

What you need. helm, curl and cub with the Workshop plugin. No account and no cluster.

1. See what you have today

You have the chart and its default values. Helm renders them like this, and the Workshop's check reads the result.

The 8 hook objects sit in the same file as everything else. Apply the file and they run at install time. The post-delete Job would remove node-feature-discovery labels from every node straight away.

KindNameHelm hook
ServiceAccountgpu-operator-node-feature-discovery-prunepost-delete
ServiceAccountgpu-operator-upgrade-crd-hook-sapre-upgrade
ClusterRolegpu-operator-node-feature-discovery-prunepost-delete
ClusterRolegpu-operator-upgrade-crd-hook-rolepre-upgrade
ClusterRoleBindinggpu-operator-node-feature-discovery-prunepost-delete
ClusterRoleBindinggpu-operator-upgrade-crd-hook-bindingpre-upgrade
Jobgpu-operator-node-feature-discovery-prunepost-delete
Jobgpu-operator-upgrade-crdpre-upgrade

The file holds no CRDs. Helm installs the chart's 5 CRDs on the first install only, and never upgrades them.

2. See what the Workshop gives you

The Catalog flattened the same chart into an OCI bundle, pinned by its digest. It holds the objects, and a plan for everything that is not an object to apply.

The plan has 4 steps.

StepWhat it does
Apply 1the 5 CRDs, then wait until each is Established
Apply 2the other 19 objects
pre-upgradeBefore an upgrade, move the CRDs to the new version. The plan names the hook objects in the signed package and never applies them with the base.
post-deleteAfter deleting, prune node-feature-discovery labels from the nodes. The plan names the hook objects in the signed package and never applies them with the base.

3. See what changed

Before, helm templateAfter, the bundle
Objects2724
Helm hook objects in the file80, named in the plan
CRDs0, installed once by helm install5, applied first
Other objects1919

The 19 other objects are the same on both sides, so the difference is the work Helm does out of sight.

4. Try it yourself, with no account

Install cub and the Workshop plugin first.

# before: render the chart as Helm does
$ helm template gpu-operator gpu-operator --repo https://helm.ngc.nvidia.com/nvidia --version v26.3.3 --namespace gpu-operator > before.yaml

$ cub config check before.yaml

# after: fetch the objects the bundle holds
$ curl -fsSL -o after.yaml https://raw.githubusercontent.com/confighub/helm-expt/main/recipes/nvidia/gpu-operator/v26.3.3/revisions/default/r001/rendered/release-objects.yaml

$ cub config check after.yaml

The bundle itself is oci://europe-west1-docker.pkg.dev/nth-fort-499605-q5/helm-expt/bundles/catalog-nvidia-gpu-operator-v26-3-3-default:r001@sha256:408cfa607e699388f62c1859f3f0daeecc99b8110f8cee076f06855be2d8ea1e, and its entry page shows the plan.

See it live in ConfigHub

Everything above runs on your own machine with no account. To see the same example in ConfigHub, load it into your own organization with the commands below.

With your own account

Here is what the command does. cub installer is an open-source plugin for the cub CLI. cub installer setup pulls a catalog package and writes its Kubernetes files locally, leaving delivery to kubectl, Argo CD or Flux. The generated scripts stop before doing any work when the plugin or kustomize is missing.

# render the base from the signed package
$ cub installer setup --pull oci://europe-west1-docker.pkg.dev/nth-fort-499605-q5/helm-expt/nvidia-gpu-operator:v26.3.3@sha256:abd8475d6bfeabe88acc2d6a319a04054a9e84046d69926dcee4717674329a8f --base default --work-dir ./nvidia-gpu-operator-v26-3-3-default --non-interactive --namespace gpu-operator

# sign in to your organization
$ cub auth login

# load the objects as a Space of Units, under names you choose
$ cub installer upload --work-dir ./nvidia-gpu-operator-v26-3-3-default --space <your-space> --component <your-component>

# list what was loaded
$ cub unit list --space <your-space>

These are the commands on the entry page. The screenshot below shows one run of them. The Catalog's own record for this entry still holds no upload.

5. Technical notes and disclaimers

  • Both checks ran on 2026-10-25 with cub v0.9.0, Workshop plugin 0.6.59 and helm v4.1.4+g05fa379. The recorded files and their receipt hold every input and output on this page.
  • No step of the plan has been run on a cluster. The plan says what a delivery workflow must do, and nothing runs it automatically.
  • This is the chart's default base. Other bases of the same version are on the entry page.
