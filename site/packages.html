Install a package

A package is a Kubernetes app, such as cert-manager, made ready for ConfigHub: all the Kubernetes objects it needs, the options it offers (for example a version without CRDs), and the questions it asks when you install it (for example which namespace). This site publishes one for every chart in its Catalog.

ConfigHub keeps your Kubernetes configuration with its history, lets you review, change and approve it, and hands it to Argo CD or Flux to deploy. Four steps put cert-manager there. To see what a package holds first, with no account, look before you install.

For agentsThe same list as data: data/ghcr-packages/packages.csv, one row per package with its chart, every published version and its registry address.

1. Install cub, ConfigHub's command-line tool

curl -fsSL https://hub.confighub.com/cub/install.sh | bash
export PATH="$HOME/.confighub/bin:$PATH"

If cub is already installed, run cub upgrade first.

2. Sign in

cub auth login

This opens your browser to sign in to ConfigHub. No account yet? Create one.

3. Install

cub package install cert-manager --space cert-manager --namespace cert-manager

This creates the Space cert-manager if it does not exist (a Space is a folder for configuration in ConfigHub), works out every object cert-manager needs, and stores each one there as a Unit you can read, change and approve. Nothing reaches a cluster until you release it.

If the package asks a question the command does not answer, cub asks it. Kubernetes Secrets the package would create are never uploaded to ConfigHub.

4. Upgrade later

cub package install cert-manager:v1.21.1 --space cert-manager
cub package show --space cert-manager

A version is written after the name, as cert-manager:v1.21.1; without one, cub installs the newest. Installing a newer version into the same Space upgrades it and keeps the answers you gave the first time. cub package show says what is installed in the Space.

Look before you install (no account needed)

This writes every object the package would install as a file on your computer. It needs no account and no cluster, and it changes nothing in ConfigHub.

cub installer setup --pull oci://ghcr.io/confighub/packages/cert-manager:v1.21.1 --namespace cert-manager --non-interactive --work-dir cert-manager
ls cert-manager/out/manifests

For cert-manager v1.21.1 that is 41 files, one per Kubernetes object.

cub installer is an open-source plugin for the cub CLI. cub installer setup pulls a catalog package and writes its Kubernetes files locally, leaving delivery to kubectl, Argo CD or Flux. If cub says it does not know installer, run cub plugin install confighub/installer first.

Check that a package is genuine

Each package is signed when it is published. cosign, the Sigstore signing tool, checks the signature:

cosign verify ghcr.io/confighub/packages/cert-manager:v1.21.1 \
  --certificate-identity-regexp '^https://github.com/confighub/helm-expt/\.github/workflows/packages-publish\.yml@refs/heads/main$' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com

This checks the package was built and signed by this repository's publish workflow, and by nothing else.

Where packages come from

Each package is built in this repository from the chart's own upstream release. Its objects are checked against what Helm renders from the same chart, and it is then published to ghcr.io/confighub/packages/<name>. A published version is never overwritten, and older versions stay published.

Every night a job checks each chart for a new upstream release. For each chart it can update on its own, it builds and checks the new package and adds it to one pull request; merging that pull request publishes the new version. A chart it cannot update is listed in an issue for a person. Nightly package updates says what a night does.

Two packages for Argo CD

  • argocd is Argo CD's own install manifests. It is published by ConfigHub's packages repository, github.com/confighub/packages, alongside flux and sveltos.
  • argo-cd-helm is Argo CD's Helm chart, published from this site.

Both install with cub package install. Use argocd unless you already run Argo CD from its Helm chart.
