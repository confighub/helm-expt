Find, compare and use nvidia/gpu-operator

The Catalog holds four versions of the Helm chart nvidia/gpu-operator, with 26 bases across them. The newest is v26.7.1.

The Catalog files this chart under Cluster operations. Its newest listing records the role gpu operator. The Deployment installs the GPU Operator and a ClusterPolicy that tells it which driver, toolkit and device-plugin workloads to run on GPU nodes; it supplies no GPU hardware.

The Catalog rendered all 26 bases and retains the exact objects of each. The listings record no upload as a variant, deployment or promoted change for any base.

Use this entry in ConfigHub in five steps, from fetching its exact objects to promoting a change.

Open a live example in ConfigHub

The example lives in the helm-catalog organization on hub.confighub.com. A reader needs access to that organization to open the links. It was observed on 2026-10-08.

It holds one component, gpu-operator, with four Spaces of 24 Units each. Three Spaces hold chart v25.10.1, v26.3.2 and v26.3.3. The fourth Space, gpu-operator-prod, was installed at chart v26.3.2 and upgraded to v26.3.3, which changed 7 of 24 Units. Its driver then changed from 580.126.20 to 595.91.07 with the Catalog base driver-595.91.07. That changed 1 of 24 Units, in the ClusterPolicy field spec.driver.version.

The component was uploaded with cub v0.8.7 from the Catalog's retained objects, on the default base with hooks excluded. The uploads were then compared with cub variant diff. Nothing was deployed to a cluster, and no Target is attached. The example is not a run for any Catalog entry, so it changes no listing state.
