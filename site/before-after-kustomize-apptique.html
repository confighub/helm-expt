Before and after

See what dev and prod Kustomize overlays become

To know what prod runs, you read 7 files and apply a JSON patch in your head. Built flat, dev and prod are two files you can read, and one table lists every field that differs between them.

What you need. kustomize, git and cub with the Workshop plugin. No account and no cluster.

1. See what you have today

The example keeps one base and two overlays in confighub/examples. Each overlay changes the base with its own namespace, label, image tag and patches.

FileWhat it holds
base/deployment.yamlthe Deployment frontend
base/kustomization.yamllists the base objects and the labels every object gets
base/service.yamlthe Service frontend and the ServiceAccount frontend
dev/kustomization.yamlsets the namespace, the environment label and the image tag, and patches the Deployment
dev/namespace.yamlthe Namespace apptique-dev
prod/kustomization.yamlsets the namespace, the environment label and the image tag, and patches the Deployment
prod/namespace.yamlthe Namespace apptique-prod

Nothing in these files says what prod runs. You find out by building it.

2. See what the Workshop gives you

Each overlay builds into one flat file of 4 objects: 1 Namespace, 1 ServiceAccount, 1 Service, 1 Deployment. The Workshop's check reads each one.

3. See every field that differs

These are all the differences between the two builds, and nothing else differs.

FielddevprodOn
metadata.labels.environmentdevprodNamespace, ServiceAccount/frontend, Service/frontend, Deployment/frontend
metadata.nameapptique-devapptique-prodNamespace
metadata.namespaceapptique-devapptique-prodServiceAccount/frontend, Service/frontend, Deployment/frontend
spec.replicas13Deployment/frontend
spec.template.spec.containers[0].imageghcr.io/confighub/apptique-frontend:v1.4.0ghcr.io/confighub/apptique-frontend:v1.3.0Deployment/frontend
spec.template.spec.containers[0].resources.limits.cpu200m400mDeployment/frontend

spec.template.spec.containers[0].resources.requests.cpu100m200mDeployment/frontend
spec.template.spec.containers[0].resources.requests.memory64Mi128MiDeployment/frontend

4. Try it yourself, with no account

Install cub and the Workshop plugin, and kustomize, first.

# fetch the example at the commit this page was built from
$ git clone https://github.com/confighub/examples.git && git -C examples checkout 7f1b8f2fc849bb6488bc2c58f1469172018fc9dd

$ cd examples/gitops/argo/intermediate-ci-to-gitops/gitops-repo/environments/apptique

# build each overlay flat
$ kustomize build dev > dev.yaml && kustomize build prod > prod.yaml

$ cub config check prod.yaml
See it live in ConfigHub

Everything above runs on your own machine with no account. To see the same example in ConfigHub, load it into your own organization with the commands below.

With your own account

5. Technical notes and disclaimers

  • The builds and checks ran on 2026-10-26 with kustomize v5.8.1, cub v0.9.0 and Workshop plugin 0.6.60, from the files on this page. The recorded files and their receipt hold every input and output.
  • cub config diff dev.yaml prod.yaml reports every object as added or removed, because the namespace is part of an object's name. The table compares objects by kind and name instead.
  • The example's own promotion record, PROMOTED_FROM.md, is not a Kubernetes object and is not on this page.
