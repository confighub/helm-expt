Where do Helm hooks and lifecycle behavior go?

Generated at: 2026-06-14T09:11:38.712Z UTC · source: committed helm-expt evidence for this hooks and lifecycle page.

The catalog does not pretend Helm hooks are ordinary static YAML. It names the lifecycle behavior, the route, who executes it, and whether the product executes it automatically.

Today a routed behavior means the route and off-ramp are visible. It does not mean universal automatic hook execution. A row becomes automatic only when the execution mode is product-owned and evidence proves that path.

Execution Mode Means Who Runs It

Execution modeRowsMeaning
not-yet-executable7The route is modeled, but no executable product path is claimed yet.
target-owned7The Kubernetes target, GitOps controller, or another controller owns the behavior.
user-executes11The user runs the lifecycle action explicitly, with receipts or checks where available.

This is the important split for Helm users. Helm may run a hook implicitly. The catalog must say whether ConfigHub runs it, the target owns it, the user runs it as an explicit lifecycle action, or the route is not executable yet.

How To Read A Route

  • Quirk: What kind of lifecycle behavior was found: hook phase, CRD install, target fact, webhook readiness, or a related class.
  • Route: Where the behavior belongs: preflight, presync, managed action, target-owned controller behavior, post-apply observation, or refusal.
  • Off-ramp: How a human or agent chooses an alternative route when the default is not right for the target.
  • Evidence: A receipt path when observed, or the next action when the route is still todo, per-target, or blocked by prerequisite work.

What To Do With This

Trying a chart

Open the chart page or matrix row. If lifecycle behavior exists, check the route and executor before treating a green render as a live install claim.

Creating a base

If the behavior changes rendered objects or Helm values, create a recipe/base variant. If it is post-render operation, route it through ConfigHub or a target-owned controller.

Using GitOps

Use Argo or Flux only when the route says the controller owns that lifecycle step or the receipt proves the selected sync path.

Automating later

Do not mark a route automatic until product execution and evidence exist. Until then, keep the explicit route and off-ramp visible.

Finding evidence

Use routes.json, summary.md, and the chart page's Hooks & Lifecycle section.
