Helm Ops made simple

Helm installs charts well. Changing them safely is the hard part: every setting has to go through values up front, and the next upgrade overwrites whatever you edited. We fix that — and you keep your Helm charts and your GitOps.

Changethe part Helm can't

Edit anything after you install — even a setting the chart never let you set — and the next upgrade keeps it. With Helm, an upgrade wipes edits like that. By hand or with an AI agent.

Operatefleet

Run many customized installs as one fleet — variants, promotions, dev/staging/prod — without re-templating each one.

# install a reviewed chart — no account
$ cub installer setup --pull packages/bitnami/redis/25.5.3 --base default --namespace app

# change a field the chart never exposed — by hand or with an AI agent
$ edit app/out/manifests/statefulset-redis-master.yaml

# upgrade to a newer chart version — your edit is still there
$ cub installer setup --pull packages/bitnami/redis/25.5.4 --merge-external-source

Why this beats "just use Helm"

With Helm, you set every field through the template up front, and the next upgrade wipes anything you changed by hand. We render the chart once, let you change anything afterward — even a field the chart never let you set — and put your change back on every upgrade. That's the one thing Helm can't do. See the four stages, F1 to F4.

And we tell you what Helm won't: every chart page lists the hooks, CRDs, prerequisites, and an honest pass / watch / blocked status — including where you'd still go back to Helm today. The honesty is the point.
